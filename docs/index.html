How Many Trees in a Random Forest?

Adaptive n_estimators tuning with triplet-based PLATEAU search and Optuna — the open-source implementation accompanying the IEEE Access 2026 paper.

Code on GitHub Paper (IEEE Access) Preprint (arXiv) Theory (arXiv)

The problem with tuning n_estimators over a range

Predictive performance of a Random Forest usually improves or stabilizes as trees are added. There is no interior optimum, so any hyperparameter optimizer — grid search, random search, TPE, Hyperband — pushes the number of trees toward whatever T_max you typed in. Too small a bound is insufficient; too large a bound wastes computation. The result depends on a guess, not on the data.

What PLATEAU search does instead

PLATEAU search removes the number of trees from the sampled search space entirely. For a current ensemble size B and scale factor sf, it evaluates the approximately geometric triplet B/sf, B, B*sf and compares out-of-bag (OOB) scores across it. Relative score changes decide whether the triplet shifts left, stays, or shifts right; meanwhile Optuna/TPE tunes the remaining Random Forest hyperparameters. The triplet settles around an ensemble size where substantially more trees buy only tolerance-level score changes.

You specify a relative tolerance ε (delta) — the score change you are willing to treat as negligible — instead of a range you cannot justify.

Install and run

pip install -e ".[dev]"
from rf_plateau_hpo.core import tune_rf_oob_plateau
from sklearn.datasets import load_breast_cancer
from sklearn.metrics import roc_auc_score

X, y = load_breast_cancer(return_X_y=True)
auc = lambda y_true, proba: roc_auc_score(y_true, proba[:, 1])

model, best_n_estimators, study, plateau_found = tune_rf_oob_plateau(
    X, y, problem="clf", score_func=auc, greater_is_better=True,
    n_estimators_start=100, scale_factor=1.5, delta=1e-3,
    max_trees=100000, n_trials=20, random_state=42, n_jobs=-1,
)
print(best_n_estimators)   # near-minimal sufficient number of trees

Frequently asked questions

How many trees does a Random Forest need?

There is no universal number. It depends on the dataset, the scoring metric, the other hyperparameters, and on how much score change you are willing to ignore. PLATEAU search makes that last quantity explicit and returns a near-minimal ensemble size meeting it.

Is the scikit-learn default of 100 trees enough?

Sometimes — but it is a default, not a decision. Whether 100 trees suffice is exactly what the plateau criterion tests, and the sufficient size also depends on the other hyperparameters being tuned at the same time.

Can too many trees make a Random Forest overfit?

Adding trees mainly reduces variance rather than increasing capacity, so the score typically improves and then flattens. The cost of an oversized forest is computational: training time, memory, and inference latency.

What range should I give Optuna for n_estimators?

With PLATEAU search, none. You give a starting size, a scale factor, a tolerance, and a safety bound; the number of trees is never sampled from a range.

How is this different from out-of-bag early stopping?

Early stopping reads a single score curve and can be sensitive to noise and prone to premature stopping. PLATEAU search accumulates information across optimization trials and uses a triplet of forest sizes, so the tree count and the other hyperparameters adapt to each other.

Related work

The question goes back to Breiman (2001) and was studied empirically by Oshiro, Perez and Baranauskas (2012), Latinne et al. (2001), Hernández-Lobato et al. (2013), and Probst, Wright and Boulesteix (2019). Those works ask how many trees are needed with the remaining hyperparameters held fixed. The contribution here is to treat ensemble size and the other Random Forest hyperparameters as interdependent and to resolve both inside a single Optuna run.
